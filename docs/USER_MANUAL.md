## 1. 快速入门

### 1.1 启动应用

**启动后端服务**：

```bash
cd backend
pip install -r requirements.txt
python run.py
```

看到以下输出表示启动成功：

```
INFO:     Uvicorn running on http://0.0.0.0:8000
INFO:     Application startup complete.
```

**启动前端**：

```bash
cd frontend
npm install
npm run dev
```

浏览器打开 **http://localhost:5173** 即可访问。

### 1.2 典型工作流程

```
步骤 1: 连接设备        → 设备管理页面添加并连接测试仪器
步骤 2: 生成测试用例     → AI 输入需求，自动生成测试用例和流程图
步骤 3: 编辑流程图       → 在流程图编辑器中调整测试步骤和逻辑
步骤 4: 执行测试         → 一键运行测试，实时监控执行状态
步骤 5: 查看日志         → 检查通信日志，确认设备交互正常
步骤 6: 生成报告         → 选择模板，导出 PDF/HTML 测试报告
```

## 3. 设备管理

### 3.1 添加设备

1. 进入 **设备管理** 页面 (`/devices`)
2. 点击 **添加设备** 按钮
3. 填写设备信息：

| 字段 | 说明 | 示例 |
|------|------|------|
| 设备名称 | 自定义名称 | `直流电源-Keysight E36313A` |
| 设备类型 | 下拉选择 | `power_supply`、`oscilloscope`、`multimeter`、`electronic_load`、`signal_generator`、`other` |
| 通信协议 | 选择协议 | `scpi`、`can`、`serial`、`ethernet`、`gpib` |
| 连接类型 | 物理接口 | `usb`、`tcpip`、`serial`、`can`、`gpib` |
| 连接地址 | 协议相关地址 | `USB0::0x2A8D::0x0101::MY12345678::INSTR` (VISA)、`/dev/ttyUSB0` (串口)、`192.168.1.100:5025` (TCP) |

4. 点击 **保存**

### 3.2 配置设备接口（连接方式）

已添加的设备可以随时更换物理接口并调整其参数 —— 在设备列表点击该行的 **编辑** 按钮（铅笔图标），
打开「配置设备接口」弹窗：

1. 选择 **接口类型**，下方参数会**按接口类型自动切换**
2. 填写对应参数后点 **保存**

支持的接口与参数：

| 接口类型 | 参数 | 说明 |
|---|---|---|
| **串口 (RS-232/485)** | 串口号（必填）、波特率、数据位、校验位、停止位、流控、超时 | 串口号形如 `/dev/ttyUSB0`、`COM3` |
| **USB** | 设备路径/虚拟串口、VID、PID、序列号、超时 | USB-CDC 会枚举成串口填设备路径；原始 USB 填 VID/PID |
| **以太网** | IP 地址（必填）、端口号、传输协议 TCP/UDP、连接超时、读取超时、**模拟模式** | 默认端口 5025；VISA 设备也可用 `TCPIP::192.168.1.100::INSTR` |
| **PCIe** | BDF 地址（必填）、设备序号、资源描述符、超时 | BDF 形如 `0000:01:00.0`，可用 `lspci` 查看 |
| **PXI / PXIe** | 机箱号、槽位号（必填）、VISA 资源串、超时 | 资源串形如 `PXI0::2::INSTR` |
| **CAN** | CAN 通道（必填）、波特率、CAN FD、超时 | 通道形如 `PCAN_USBBUS1`、`can0` |
| **GPIB** | VISA 资源串（必填）、GPIB 地址、超时 | 形如 `GPIB0::1::INSTR` |

注意事项：

- **切换接口会清空其它接口的地址字段**（例如从串口切到以太网后，串口号会被清空），
  同时移除其它接口的参数（不会把波特率留给 TCP 连接），避免残留配置干扰
- **PCIe / PXI 当前为模拟模式**：尚未接入内核驱动/机箱控制器，连接会成功，
  但收发返回带 `[Simulated PCIe:...]` / `[Simulated PXI...]` 标记的数据，用于验证流程正确性
- **以太网也可开「模拟模式」**：没有真实设备时勾选后连接必定成功、返回模拟数据；
  不勾选时连接失败会**如实报错**（早期版本会假装连上并返回假数据，已修复）

### 3.3 连接设备

在设备列表中，点击目标设备的 **连接** 按钮。

- 状态变为 **已连接**（绿色指示）
- 侧边栏底部设备状态指示器同步更新

### 3.4 发送命令

> 💡 通信日志（第 8 章）在数据量很大时已启用虚拟滚动，每页可调到 200 条仍保持流畅。

1. 进入设备详情页
2. 在命令输入框中输入 SCPI/CAN 等协议命令
3. 点击 **发送**
4. 响应结果显示在下方

**示例命令**：

```
# 可编程电源
*IDN?                           # 查询设备身份
VOLT 5.0                        # 设置输出电压 5V
MEAS:VOLT?                      # 读取实际电压

# 示波器
:CHAN1:SCAL 1.0                # 设置通道1垂直刻度
:WAV:DATA?                     # 获取波形数据
```

### 3.5 断开设备

在设备详情页点击 **断开连接**，或在设备列表点击断开按钮。

### 3.6 删除设备

在设备列表中，点击 **删除** 按钮并确认。

### 3.8 界面语言（中文 / English）

顶栏右侧的语言下拉可在**中文**与 **English** 之间切换。选择会记入浏览器本地存储，
下次打开自动沿用；antd 组件与日期选择器会一并切换。

已翻译范围：左侧导航、通用动作（刷新/添加/删除/保存/取消等）、设备管理、项目工程、
设备接口参数。尚未接入翻译的页面会按回退策略显示中文（不会出现空白或原始键名）。

### 3.7 Mini Gateway 100：串口 / 以太网切换

Mini Gateway 100 由插件驱动，两种物理链路共用同一套协议，通过插件配置里的 **`transport`** 切换：

| `transport` | 参数 | 默认值 |
|---|---|---|
| `serial`（默认） | `port`（串口号）、`baudrate` | `/dev/ttyACM0`（Windows 为 `COM3`）、115200 |
| `ethernet` | `host`、`tcp_port`、`connect_timeout` | `192.168.0.120`、`6025`、5.0 s |

公共参数：`board_id`（默认 11）、`timeout`（默认 2.0 s）。

> ⚠️ 注意：串口号占用的是 `port` 键，所以以太网 TCP 端口的键名是 **`tcp_port`**，两者不要混淆。

切换方式：在设备列表进入该设备的配置（或「添加设备」时由插件模板生成），把 `transport` 改为
`ethernet` 并填写 IP 与端口即可。以太网不通时会给出可操作报错（超时 / 不可达分别提示），
不会像早期版本那样假装连上。

### 3.9 右侧「输出 / 交付」抽屉

测试执行与输出报告不占左侧菜单，而是收在页面**右侧的抽屉**里：

| 操作 | 效果 |
|---|---|
| **单击**收起态竖条 | 展开（`min(720px, 58vw)`，按窗口宽度收敛） |
| **双击**收起态竖条 | 直接全屏 |
| 展开态的 **全屏** 按钮 | 铺满工作区（`Esc` 退出） |
| **图钉** 按钮 | 钉住后切换左侧菜单时保持展开；未钉住则切页自动收起 |

- 两个 Tab：**测试执行**（启动/暂停/停止、进度、实时结果）、**输出报告**（模板、格式、生成导出）
- 收起态竖条会显示**运行中任务数**（> 0 时琥珀色徽标）
- 任意页面点「启动执行」→ 抽屉**自动展开**并切到「测试执行」Tab

### 3.10 ⌘K / Ctrl+K 命令面板

按 **⌘K**（macOS）或 **Ctrl+K**（Windows/Linux）唤起，也可以点顶栏的放大镜图标。

- 搜索范围：左侧导航 8 项、顶栏 2 项、输出区 2 个 Tab、**设备**（按设备ID号或名称）、**测试用例**（直达流程图）
- `↑` `↓` 选择，`Enter` 打开，`Esc` 关闭
- 侧栏只有 8 项，深层页面（报告、日志、某个具体用例）用命令面板最快

### 3.11 插件中心（三页合一）

插件管理、插件编辑器、Skill 编辑器已合并为**一个「插件中心」页面**，顶部三个 Tab 切换。

> 旧的 `/plugin-editor`、`/skill-editor` 地址仍然可用，会自动落到对应 Tab，老链接不会失效。

### 3.12 流程图沉浸模式

进入某个用例的**流程图编辑器**时，左侧栏会自动收起、右侧抽屉让位，把空间全部留给画布。
需要菜单时点顶栏的 **「退出沉浸」** 即可恢复。

## 4. 测试用例管理

### 4.1 手动创建测试用例

1. 进入 **测试用例** 页面 (`/testcases`)
2. 点击 **新建用例**
3. 填写：

| 字段 | 说明 |
|------|------|
| 用例名称 | 简短描述性名称 |
| 需求描述 | 详细的测试需求说明 |
| 参数配置 | JSON 格式，定义测试参数 |

**参数配置示例**：

```json
{
  "input_voltage": 12.0,
  "expected_output": 5.0,
  "tolerance": 0.1,
  "load_current": 1.0
}
```

### 4.2 编辑测试用例

点击用例行进入详情页，可修改名称、需求描述和参数配置。

### 4.3 删除测试用例

（略，见界面操作）

### 4.4 设备ID号：用例如何关联设备

每个设备都有一个**设备ID号**（如 `DEV-001`、`DEV-002`），它是设备的**稳定唯一标识**，
显示在「设备管理」列表的第一列，点击即可修改。

- **用例通过设备ID号关联设备**，而不是通过系统内部的主键
- **更换硬件时，把同一个设备ID号赋给新设备**，原有用例即可继续使用，无需逐个修改
- 若确实要改用另一台设备，用下面的「切换设备」功能

> 为什么需要它：设备删除后重新添加会拿到新的内部 ID。如果用例绑定的是内部 ID，
> 每次换设备都会让绑定失效——表现为"用例能启动、但通信窗口一条消息都没有"。
> 设备ID号把这个隐患从根上消除了。

### 4.5 切换设备（并自动重新生成代码）

在测试用例列表每行点击 **切换设备**（双向箭头图标）：

| 字段 | 说明 |
|---|---|
| 切换到（目标设备ID号） | 必填，选择要改用哪台设备 |
| 仅切换当前绑定（可选） | 只改绑定该设备的步骤；留空则改本用例**全部**已绑定步骤 |

点击 **切换并重新生成代码** 后，系统会：

1. 把匹配的流程步骤重新绑定到目标设备
2. **立即按新设备重新生成代码**并返回（切换与重新生成是一个原子操作，
   不会出现"设备换了、代码还是旧的"）
3. 显示切换了多少个步骤，以及新代码的长度

相关接口（供脚本/集成使用）：

```bash
# 按设备ID号切换（返回重新生成的代码）
curl -X POST http://localhost:8000/api/testcases/{用例ID}/switch-device \
  -H 'Content-Type: application/json' \
  -d '{"to_device_key":"DEV-002","from_device_key":"DEV-004"}'

# 把旧的内部ID绑定翻译成设备ID号（幂等）
curl -X POST http://localhost:8000/api/testcases/backfill-device-keys

# 查看是否存在失效绑定
curl http://localhost:8000/api/testcases/stale-devices
```

在用例列表中点击 **删除** 并确认。关联的流程图数据也会一并删除。

## 5. AI 生成测试用例

### 5.1 文字输入生成

1. 进入 **测试用例** 页面
2. 点击 **AI 生成** 按钮
3. 在输入框中输入测试需求，例如：

> 测试 DCDC 电源模块的输出电压，输入 12V，输出应为 5V ± 0.1V，负载 1A。需要分别测试空载、半载和满载三种工况。

4. 点击 **生成**
5. AI 自动生成：
   - 结构化的测试用例（名称、描述、参数）
   - 可视化流程图（测试步骤节点和连线）

6. 检查生成结果，点击 **确认保存**

### 5.2 语音输入生成

1. 点击 **AI 生成** 按钮
2. 点击麦克风图标开始录音
3. 说出测试需求
4. 再次点击停止录音
5. 系统自动转写并生成测试用例

### 5.3 提示词技巧

为获得更好的 AI 生成效果，建议在需求描述中包含：

- **被测对象**：设备/模块名称和类型
- **输入条件**：电压、电流、信号参数
- **预期输出**：期望值和容差范围
- **测试条件**：负载、温度、时序等
- **测试步骤**：操作顺序

### 5.4 预览生成的测试用例

在 **AI 助手** 页面点击「生成测试用例」后，切到 **生成的测试用例** 页签，
每个用例右侧都有 **预览** 按钮，打开后可查看完整内容再决定是否入库：

- 用例名称、描述、**整体预期结果**、需要设备、标签
- **步骤表**：步骤号、动作、命令 / 参数、预期结果、节点类型（`action`/`delay`/`condition`/`loop`）
- 流程说明（若 AI 提供）

预览弹窗底部可直接点 **添加到测试用例列表**，无需返回列表页再操作。

### 5.5 一键添加

- **一键添加全部**：把当前这批用例（含各自流程图）一次性写入测试用例列表
- **添加**（单个）：只添加该条用例

### 5.6 通过对话进一步修改测试用例

生成结果不必一次到位。在 **生成的测试用例** 页签里有一个 **继续修改** 输入框，
用自然语言描述修改意见即可，例如：

> 把第 2 步的等待时间从 1000ms 改成 500ms，并在最后增加一个步骤：读取版本号

点击 **应用修改** 后，AI 会返回**修改后的完整用例集**并整体替换当前结果，
确认无误后再点「一键添加全部」。

说明：

- 每次修改都会记录在「已应用的修改」中，可追溯改了什么
- 若 AI 返回的内容无法解析，系统会**保留原用例**并给出提示，不会清空已有成果
- 修改过程会同步出现在「对话」页签，便于回溯

### 5.7 项目记忆文件（`Project_xxx Memory.md`）

**项目记忆** 页签用于把对话中确认的关键内容沉淀成 Markdown 文件，
保存在 `backend/memory/Project_<项目名> Memory.md`，可直接提交到 Git。

1. 填入 **项目名**（默认 `AITestLab`）
2. 点 **从对话提炼要点**：AI 会把当前对话归纳为四类 —— **决策 / 约定 / 事实 / 约束与风险**，
   并自动跳过已有记忆中记录过的内容
3. 提炼结果出现在下方文本框，**可直接编辑修改**
4. 确认后点 **写入记忆文件**（追加模式，每次带 `## 时间 · 标题` 小节）
5. 下方「已有记忆文件」可 **查看** 全文或 **删除**

### 5.8 添加文件与图片

AI 助手的**输入区固定在页面下方**（上方是 AI 的回复与生成结果），
在输入框上可以附加文件：

- 点输入框左侧的 **附件** 按钮选择文件，**或直接把文件拖进输入区**
- 支持多选；单个文件上限 **10 MB**
- 已添加的文件显示在输入框上方，可逐个移除（图片会显示缩略图）

不同附件的处理方式：

| 附件 | 处理 |
|---|---|
| 文本文件（`.txt` `.md` `.csv` `.log` `.json` `.py` `.yaml` `.xml` …） | 内容以内联正文块形式交给模型，模型可直接引用其中的数值 |
| 图片 | 以多模态内容发送，模型可以"看"图（前提是所选模型支持视觉） |
| 超长文本 | 截断到 12 万字符并标注 |

> 如果当前模型不支持图片输入，系统会**自动忽略图片并按文字内容重新回答**，
> 并在回复开头加提示，而不会直接报错。

### 6.3 节点类型

#### 节点在画布上如何区分（Issue #22）

节点类型靠**图标 · 形状 · 填充模式**区分，而不是各用一种颜色 —— 全站只有 3 个色系
（石墨灰 / 仪器蓝 / 琥珀），红色专属于「失败 / 错误」，所以**结束节点不再是红色**。

所有节点统一为**石墨灰底 + 白色文字**，靠**边框样式 · 形状 · 明度**区分类型。

| 类型 | 底色 | 编码方式 | 看黑白截图能否区分 |
|------|------|---------|:--:|
| 开始 | 石墨灰 | **2px 仪器蓝描边** | ✅ 粗边框 |
| 初始化 | 石墨灰（浅一档） | 1px 仪器蓝描边 | ✅ 更浅 |
| 操作 | 石墨灰 | 1px 石墨灰描边 | ✅ 标准 |
| 判断 | **仪器蓝** | **菱形**（形状 + 蓝色双重编码） | ✅ 形状 |
| **循环** | 石墨灰 | **1px 琥珀描边 + 左侧 3px 琥珀色条** + 琥珀图标 | ✅ 唯一琥珀 |
| 延时 | 石墨灰 | **虚线**边框 + 弱化白字 | ✅ 虚线 |
| 结束 | 石墨灰（深一档） | 弱化白字 | ✅ 更深 |

**连接点**：所有节点的上/下连接点统一为**仪器蓝**（`#2296C4`）；鼠标悬停或节点被选中时
变亮（`#8FCBEA`）并出现 3px 光晕，方便抓取。

> **琥珀只给「循环」**。循环决定一段流程重复多少次，问题也最常发生在循环边界，
> 给它一个视觉锚点最划算；其余类型一律不新增色相。

#### 循环 ≠ 运行中

琥珀在系统里的既定语义是「运行中 / 需注意」，两者走**不同的形态通道**，不会混淆：

| | 形态 | 动/静 |
|---|---|---|
| **循环**（类型） | 静态琥珀描边 + 左侧 3px 色条 + 琥珀图标 | **静止不动** |
| **运行中**（状态） | 节点外圈**脉冲光晕** + 右上角旋转角标 | **动态可见** |
| **失败**（状态） | 红色外圈 | 静止 |

#### 工具栏分组

工具栏按语义分为 5 组，用竖线分隔：

**① 历史**（撤销 `UndoOutlined` / 重做 `RedoOutlined`）· **② 编辑**（复制 / 粘贴 / 创建副本）·
**③ 危险**（删除选中）· **④ 视图**（全屏）· **⑤ 提交**（保存流程图 / 生成代码）

- 撤销与重做现在是各自的原生图标（此前「返回」与「撤销」共用同一个左箭头，重做则是它水平翻转）
- 节点面板宽 148px，鼠标悬停会抬升，按住时显示「抓取」手型

## 7.5 执行管理器（批量编排）

> v0.9.0 新增。入口：左侧菜单 **执行管理器**（`/execution-plans`）。

一次性挑选多个测试用例，编排它们的**执行顺序、并行关系、循环次数与延时**，批量运行。
系统会在执行前**静态识别「同一设备（或同一端口）被多个并行用例占用」并报警**，冲突未处理时禁止执行。

### 7.5.1 界面三栏

| 区域 | 作用 |
|------|------|
| 左：用例库 | 搜索并勾选用例 → 点「加入计划」；下方「已有计划」可打开/继续编辑历史计划 |
| 中：执行序列 | 每个计划项一行，可调顺序、并行组、设备、循环次数、三种延时 |
| 右：校验面板 | 实时显示冲突 / 警告 / 预估时长，「开始执行」按钮在有冲突时禁用 |

### 7.5.2 并行分组（核心概念）

**计划项按 `组` 号升序执行；组内并行，组间串行。**

- 新加入的项默认是各自的组号 → **全串行**（与原有单用例逐个跑行为一致）；
- 点行内 **↰** 把该项并入上一项的组 → 两者**并行**；
- 点 **⇥** 让它独立成组 → 恢复串行。

> v1 不支持「第 1 项与第 3 项并行、第 2 项夹在中间」这类交错编排。

### 7.5.3 循环与延时（单位毫秒）

| 配置 | 说明 |
|------|------|
| 循环次数 | 该项重复执行 N 次，**迭代之间串行**，范围 1–10000 |
| 前置延时 | 本项**开始前**等待（等设备上电/稳定），**项级**，不是每次迭代都等 |
| 循环间隔 | 相邻两次迭代之间等待 |
| 后置延时 | 本项**结束后**等待 |

时序：`前置延时 → 迭代1 → 间隔 → 迭代2 … → 迭代N → 后置延时`

全局配置还有：**计划循环**（整份计划重复跑几轮）、**最大并行度**（1–16，默认 4）、
**失败策略**（停止全部 / 继续 / 停止本组）。

### 7.5.4 设备列三态

| 状态 | 含义 | 处理 |
|------|------|------|
| 🟢 已确定 | 解析到具体设备 | 可直接参与并行 |
| 🟡 多候选 | 协议匹配到多台设备 | 建议手工指定 1 台（并行下会给黄色警告） |
| 🔴 未指定 | 推断不出设备 | **不能与其它项并行**（红色阻断）；串行时沿用旧自动选择逻辑 |

手动点设备下拉可覆盖；设备增减后可在服务端调用 `/api/execution-plans/{id}/resolve-devices` 重新推断。

### 7.5.5 冲突报警

同一并行组内，只要**资源键相交**就报警：

| 错误 | 触发场景 |
|------|----------|
| `DEVICE_CONFLICT` | 同一台设备被 2 个并行用例占用 |
| `PORT_CONFLICT` | **两台不同的设备占用了同一端口**（串口 / CAN 通道 / VISA / IP:端口） |
| `UNRESOLVED_DEVICE_IN_PARALLEL` | 并行组内有未指定设备的项 |
| `PARALLEL_LIMIT_EXCEEDED` | 组内项数超过「最大并行度」 |
| `DUPLICATE_CASE_IN_GROUP` | 同一用例在同一并行组内重复 |

处理办法：点校验面板的 **自动串行化(推荐)**（把冲突项按顺序拆成连续独立组，保持相对顺序），
或手工调整分组 / 指定设备。黄色警告（设备离线、多候选、空流程）不阻断，但会二次提醒。

> **后端独立校验**：即使绕过界面直接调用 `POST /api/execution-plans/{id}/run`，
> 存在冲突时后端仍返回 **409**，不会启动执行。

### 7.5.6 运行监控

点右上角菜单可打开「批量运行监控」抽屉（2 秒轮询）：显示批次状态、总体进度、
通过/失败统计、耗时，以及每个计划项的实时状态与**迭代进度 k/N**。
点任一迭代产生的执行记录可下钻到原有的单执行详情页。

每次迭代都会生成一条独立的执行记录，带 `plan_run_id`/`iteration`/`group_no`；
**单用例立即执行产生的记录这些字段为空**，原有执行列表与统计口径不受影响。

2. 在插件管理页面点击 **安装插件**
3. 输入插件文件路径，如 `plugins/my_protocol.py`
4. 点击 **安装**

### 12.3 启用/禁用插件

在插件列表中点击 **启用** / **禁用** 开关。禁用的插件不会出现在设备连接协议选项中。

### 12.4 卸载插件

点击插件行的 **卸载** 按钮并确认。注意：已使用该插件的设备将无法正常连接。

### 12.5 开发自定义插件

参考 `backend/plugins/example_plugin.py`，完整示例：

```python
"""
Modbus RTU 协议插件示例。
放入 backend/plugins/ 目录后通过 API 安装即可使用。
"""
import asyncio
from typing import Optional
from app.communication import CommunicationInterface


class ModbusRTUPlugin(CommunicationInterface):
    name = "modbus_rtu"
    description = "Modbus RTU 串行通信协议 (RS485)"

    def __init__(self):
        self._serial = None
        self._connected = False

    async def connect(self) -> None:
        import serial_asyncio
        self._reader, self._writer = await serial_asyncio.open_serial_connection(
            url=self.config.get("port", "/dev/ttyUSB0"),
            baudrate=self.config.get("baudrate", 9600),
            bytesize=self.config.get("bytesize", 8),
            parity=self.config.get("parity", "N"),
            stopbits=self.config.get("stopbits", 1),
        )
        self._connected = True

    async def disconnect(self) -> None:
        if self._writer:
            self._writer.close()
        self._connected = False

    async def send(self, command: str) -> None:
        data = self._build_modbus_frame(command)
        self._writer.write(data)
        await self._writer.drain()

    async def receive(self) -> str:
        response = await self._reader.read(256)
        return self._parse_modbus_frame(response)

    def _build_modbus_frame(self, command: str) -> bytes:
        # Modbus RTU 帧构建逻辑
        parts = command.split()
        slave_id = int(parts[0])
        func_code = int(parts[1])
        # ... CRC 计算等
        return b""

    def _parse_modbus_frame(self, data: bytes) -> str:
        # Modbus RTU 帧解析逻辑
        return data.hex()

    @property
    def is_connected(self) -> bool:
        return self._connected
```

## 13. 常见问题

### 13.1 设备连接失败

**问题**：点击连接后提示"连接失败"或"超时"

**排查步骤**：
1. 确认设备已开机并正确连接到电脑
2. 检查连接地址是否正确（VISA 地址可通过 `pyvisa-shell` 或 NI MAX 查看）
3. 确认设备驱动已安装（NI-VISA 或 PyVISA-py 后端）
4. Linux 下检查串口权限：`sudo usermod -a -G dialout $USER`
5. 检查设备是否被其他程序占用

### 13.2 CAN 设备无法识别

**问题**：CAN 接口未在可用设备列表中显示

**排查步骤**：
1. Linux：确认 `can-utils` 已安装，`sudo ip link set can0 up type can bitrate 500000`
2. Windows：确认 PCAN 驱动已安装
3. 检查 `python-can` 配置：`python -m can.viewer` 测试
4. 确认 CAN 终端电阻已正确接入（120Ω）

### 13.3 AI 生成结果不理想

**问题**：AI 生成的测试用例不准确或流程图结构混乱

**改进方法**：
1. 提供更详细的需求描述（包含设备类型、参数范围、测试步骤）
2. 尝试不同的 AI 模型（大模型通常效果更好）
3. 使用流程图编辑器手动调整 AI 生成的结果
4. 将复杂测试拆分为多个较小的用例

### 13.4 Ollama 连接问题

**问题**：配置 Ollama 模型后无法连接

**排查步骤**：
1. 确认 Ollama 服务正在运行：`curl http://localhost:11434/api/tags`
2. 确认模型已拉取：`ollama list`
3. 检查 API 地址格式：应为 `http://localhost:11434/v1`
4. 检查防火墙设置是否阻止了 11434 端口

### 13.5 语音输入无反应

**问题**：点击麦克风后无法录音

**排查步骤**：
1. 确认浏览器已授予麦克风权限
2. 确认系统麦克风正常工作
3. 检查 Whisper 模型是否已下载（首次使用会自动下载 `base` 模型）
4. 手动下载 Whisper 模型：`python -c "import whisper; whisper.load_model('base')"`

### 13.6 数据库问题

**问题**：启动时数据库报错

**解决方案**：
```bash
# 删除旧数据库重新初始化（注意：会丢失所有数据）
rm backend/aitestlab.db
# 重启后端，自动创建新数据库
python backend/run.py
```

### 13.7 端口被占用

**问题**：启动时提示 `Address already in use`

**解决方案**：
```bash
# 查找占用端口的进程
lsof -i :8000  # Linux/macOS
netstat -ano | findstr :8000  # Windows

# 终止进程
kill -9 <PID>  # Linux/macOS
taskkill /PID <PID> /F  # Windows
```

### 13.8 用例能启动，但通信窗口没有任何消息

**现象**：执行开始了，步骤却直接失败，通信窗口一片空白，一条报文都没有。

**常见根因：流程里绑定的设备已经不存在了。**

设备**删除后重新添加会拿到新的 ID**（名称和协议不变）。而流程节点把设备写死在
`config.device_id` 上，于是所有指向旧 ID 的流程都变成"悬空绑定"：

- 执行时引擎拿旧 ID 去发指令 → `Device xxx is not connected` → 步骤失败
- **一条指令都没真正下发，所以通信窗口自然什么都没有**

**如何发现**：进入 **测试用例** 页面，如果存在失效绑定，顶部会出现黄色告警条
「有 N 个用例绑定了已不存在的设备」，点击其中的 **重新绑定设备** 即可一键修复
（按每个节点命令推断出的协议，改指向当前的设备）。

**手动确认 / 修复**（也可直接用接口）：

```bash
# 只查看，不改数据
curl http://localhost:8000/api/testcases/stale-devices

# 执行重新绑定
curl -X POST http://localhost:8000/api/testcases/rebind-devices
```

**其它可能原因**（告警条没出现时再排查）：

- 步骤绑定的设备**存在但没连接** → 提示会点名该设备，先去「设备管理」连接它
- 步骤本身不含可下发的指令（例如"汇总显示结果"）→ 状态为 `skipped`，属正常跳过
- 协议无法识别（命令既不像 `@11_…` 也不像 CAN JSON）→ 提示"未找到已连接的 X 设备"

## 14. 项目工程文件

**项目工程** 把散落在各处的配置打包成**一个 JSON 文件**，方便备份、迁移和团队共享。

包含 7 个配置段（导出时可勾选）：

| 配置段 | 内容 |
|---|---|
| 模型配置 | AI 模型（**不含 api_key**） |
| 设备配置 | 设备定义与参数 |
| 插件配置 | 插件注册表与其配置 |
| Skill 配置 | 插件 Skill 与手册 Markdown |
| 测试用例 | 用例本体 **+ 对应流程图** |
| 执行管理器 | 执行计划与其全部计划项 |
| 仪表盘配置 | 自定义仪表盘布局与挂件 |

### 14.1 导出

1. 进入 **项目工程** 页面（左侧菜单）
2. 勾选需要包含的配置段（默认全选）
3. 点 **导出当前配置（下载文件）**，浏览器会下载 `Project_<名称>.json`

### 14.2 另存为

点 **另存为工程…** 并输入工程名，系统会导出当前配置并**同时**在服务端
`backend/projects/` 保存一份 `Project_<工程名>.json`，之后可在列表中直接管理它。

### 14.3 导入

- **导入工程文件…**：选择本地的 `.json` 文件上传
- 列表中每个工程右侧的 **导入**：直接把服务端保存的该工程写回系统

导入模式二选一：

- **合并导入**（默认）：按 `id` 匹配，找不到再按名称匹配；已存在则更新、不存在则新建。
  **重复导入不会产生重复数据**（幂等）
- **替换导入**：先清空该配置段再写入，**会删除该段现有数据**，请谨慎使用

导入完成后会显示每个配置段「新建 / 更新 / 跳过」的条数。

### 14.4 重命名、覆盖与删除

| 操作 | 说明 |
|---|---|
| **重命名** | 改工程名（文件与内部 `project_name` 同步更新） |
| **覆盖** | 用**当前系统配置**覆盖该工程文件（相当于重新导出并保存） |
| **下载** | 把服务端保存的工程文件下载到本地 |
| **删除** | 删除该工程文件 |

### 14.5 项目向导

点 **项目向导** 按三步创建新工程：

1. **选择配置段** —— 勾选要打包进工程的内容
2. **命名工程** —— 保存为 `Project_<名称>.json`
3. **确认生成** —— 复核后点「生成工程」

> 向导只是把当前配置**另存为一份工程文件**，不会改动系统里的现有配置。
> 如果想清空工作区从零开始，请用「新建项目工程」。

### 14.6 新建项目工程

点 **新建项目工程** 可以清空工作区、从零开始一个新项目。

- **默认保留 AI 模型配置**（接口地址与 API Key 属于环境配置，不是项目数据）。
  弹窗里可取消勾选以连带清除模型配置。
- 会被清空：设备、插件、Skill、测试用例（含流程图）、执行计划、仪表盘
- **不会**被清空：执行历史、通信日志、报告
- 操作不可撤销，必须显式确认；完成后会列出每个配置段的清除条数与保留项

### 14.7 安全说明

- AI 模型的 **`api_key_encrypted` 永远不会被写入工程文件**，导入时也不会覆盖已有的密钥
- 导入时会跳过机器相关字段：插件的 `file_path` / `module_name`、设备的 `status` / `last_seen`，
  避免导入后出现「设备显示已连接但实际未连接」的情况
